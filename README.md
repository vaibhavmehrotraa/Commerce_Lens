# CommerceLens

**E-commerce Purchase, Customer Value & Probability Intelligence** — a portfolio analytics product that treats
customer behavior as a probability problem, not just a reporting problem.

CommerceLens is a full-stack analytics application built on a 60,000-session synthetic e-commerce dataset. It
walks the complete analytical path most dashboards skip — data → customer behavior → statistical description →
association → probability → uncertainty → business decision — with every number on the site computed live from
the dataset, never hand-typed.

## Business problem

*How can an e-commerce marketplace use customer behavior and probability-based analytics to understand purchase
behavior, estimate customer value, quantify uncertainty, and make better customer targeting and operational
decisions?*

Most internal dashboards stop at descriptive reporting: conversion rate, revenue, AOV. CommerceLens goes further
— conditional probability, Bayes' theorem, random variables, and distribution modeling — to answer the
probability-shaped questions a business actually needs answered to act under uncertainty: what's the probability
a session converts given an observed behavior, how many conversions should N future sessions produce, what's the
chance a finite-pool campaign sample contains enough high-value customers, which behavioral signals are
genuinely associated with purchase.

## Why this project exists

It's a portfolio piece built to demonstrate business analytics, product analytics, statistics, probability, and
data visualization skill together — not as a classroom statistics assignment, but as something that reads like a
real analytics product a Business Analyst / Product Analyst / Data Analyst could walk a hiring manager through.
See the full write-up at [`/case-study`](web/app/case-study/page.tsx) on the running site.

## Dataset

- 60,000 session-level rows, 53 columns (raw + derived), generated by a seeded, reproducible Python script
  (`data/generate_dataset.py`) with intentional, realistic statistical dependencies — not independent noise.
- Validated by 33 automated integrity checks (`data/validate_dataset.py`) — all passing.
- Fully documented in [`data/data_dictionary.csv`](data/data_dictionary.csv) / [`docs/data_dictionary.md`](docs/data_dictionary.md).

## Statistical concepts → Business questions

| Statistical concept | Business question it answers | Where |
|---|---|---|
| Mean, median, mode, percentiles, IQR, outliers | What does a typical order look like, and which orders are unusual? | `/descriptive` |
| Correlation, covariance, fitted line | Do session duration and products viewed move together? Does that translate to order value? | `/association` |
| Chart design pitfalls | How can the *same* numbers be made to look dramatically different? | `/misleading-charts` |
| Set-theoretic & conditional probability | What's the chance a session purchases, given it added to cart? | `/probability` |
| Bayes' theorem | Do two independent ways of computing P(Purchase\|Cart) agree? | `/bayes` |
| Empirical independence | Are discount exposure and purchase behaving independently? | `/independence` |
| Permutations & combinations | How many ways can we assign offers to segments, or sample a campaign list? | `/combinatorics` |
| PMF, CDF, expectation, variance, Bernoulli | What's the expected number of items per purchase, and how much does it vary? | `/random-variables` |
| Binomial distribution | Out of the next 500 sessions, how many conversions should we expect — and with what spread? | `/binomial` |
| Hypergeometric distribution | Sampling 40 of 500 campaign customers without replacement — what's P(≥k high-value)? | `/hypergeometric` |
| Uniform / Triangular / Exponential | How do we model a bounded arrival window, delivery-time uncertainty, or time between purchases? | `/distributions` |
| Rule-based segmentation | Who are New / Occasional / Regular / Loyal customers, by an explicit, auditable rule? | `/segmentation` |
| Revenue, AOV, return rate, distributions | Where is customer value concentrated, and how much does it vary within a segment? | `/customer-value` |
| Statistics → decision framing | What should a decision-maker actually do with each finding — and what should they be careful about? | `/decision-lab` |

## Key insights

See [`docs/business_insights.md`](docs/business_insights.md) for the full, numbers-cited summary. Headline:
27.5% conversion rate, ₹4,685 average order value against a ₹1,350 median (a right-skewed distribution),
P(Purchase\|Cart) = 55.0% vs. a 27.5% baseline, and a discount-exposure/purchase relationship that fails an
empirical independence check — all framed as observational associations in a specific sample, never as causal
claims.

## How to run

```bash
# 1. Python environment
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. Generate the dataset (writes data/commerce_sessions.csv + .parquet)
python data/generate_dataset.py

# 3. Validate it (writes data/validation_report.json; exits non-zero on failure)
python data/validate_dataset.py

# 4. Run the analytics test suite (60 tests)
python -m pytest analytics/tests/

# 5. Run every analytics module against the real data (writes analytics/output/analytics.json)
python -m analytics.run_all

# 6. Sync the computed output + raw CSV into the web app
cp analytics/output/analytics.json web/lib/data/analytics.json
cp data/commerce_sessions.csv web/data/commerce_sessions.csv

# 7. Install, test, and start the website
cd web
npm install
npm test         # runs the TypeScript analytics test suite (lib/analytics/__tests__/run.ts)
npm run dev      # http://localhost:3000
# or: npm run build && npm start
```

## Limitations

CommerceLens is a demonstration of analytical method on a **synthetic, observational** dataset — not a market
research report. Full list (synthetic data, non-experimental design, distributional/independence assumptions,
sample-dependent empirical probabilities, and model-specific caveats for the binomial, hypergeometric, uniform,
triangular, and exponential sections) is in [`docs`](docs) and rendered on the site at `/limitations`.

## Future improvements

- Swap the synthetic generator for a real, anonymized transaction log to validate whether the same statistical
  patterns hold outside a designed dataset.
- Add a lightweight experimentation module (A/B test power/sample-size calculator) to complement the observational
  analyses.
- Persist Data Explorer filter state in the URL for shareable, bookmarkable queries.
- Add cohort/retention curves and a proper survival-analysis treatment of the next-purchase waiting time, instead
  of the illustrative exponential model.
